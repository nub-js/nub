Nub runs approved dependency install scripts in a build jail. It is enabled by default on macOS, Linux, and Windows, with no setup command or administrator access.

```sh
nub install
```

## Build approval

Approval decides which dependencies may run scripts. The build jail limits the access those scripts receive.

```sh
nub approve-builds
```

The command records approval and runs the approved scripts. To declare approval in the project's `package.json`:

```json title="package.json"
{
  "allowScripts": {
    "esbuild": true,
    "sharp": true
  }
}
```

These entries approve scripts without disabling the build jail. See [lifecycle scripts](/docs/install#lifecycle-scripts) for approval rules and the default-trust floor.

## Permissions

Each script receives access to its package directory and the tools needed to build it. Nub's package catalog adds filesystem and network permissions for dependencies that need them.

- Build scripts run on plain Node.
- Credential variables such as `NPM_TOKEN` and `AWS_SECRET_ACCESS_KEY` are removed.
- Scripts receive a build-specific home and temporary directory.
- Root-project scripts, such as `prepare`, run with the project's ordinary permissions.

The jail reduces exposure to malicious install scripts; it is not isolation for arbitrary untrusted code. On Windows, native-tool compatibility grants can remove filesystem and network isolation while retaining environment filtering and process cleanup.

### Automatic filesystem grants

Nub selects catalog permissions by package name, version, and operating system when it compiles a build script's policy. Some broad catalog grants use directory enumeration to omit known credential locations:

| Catalog grant | Expansion |
| --- | --- |
| Read the disk | Enumerate allowed siblings around known credential locations. |
| Read or write the real user home | Apply the same enumeration within the user's home directory. |
| Write the disk | Remove filesystem confinement; no credential-location exclusion remains. |

These are internal catalog permissions, not settings in a dependency's `package.json`. The real user home is distinct from the build-specific home assigned to the script.

For example, the home-directory expansion omits `~/.ssh`, descends into `~/.config` to omit `~/.config/gh`, and grants the unaffected siblings:

```text
~/
  .ssh/                 omitted
  .config/
    gh/                 omitted
    editor/             allowed subtree
  projects/             allowed subtree
  notes.txt             allowed
```

The exclusion list names credential locations such as `.ssh`, `.gnupg`, `.aws`, `.git-credentials`, `.npmrc`, `.kube`, `.config/gcloud`, `.config/gh`, browser profiles, and macOS Keychains. The compiler also checks immediate home and project entries for `.env*` and npm configuration files. It lists directory children and descends toward known exclusions; it does not inspect file contents or recursively search every directory for secrets.

This expansion happens during policy compilation, not on every file operation. A new top-level sibling may therefore be inaccessible, while a new file inside an already granted subtree is accessible—even if that file contains credentials. Another broad grant can also include a location omitted by this expansion. Filtering environment variables does not prevent reading credentials from an allowed file.

<Callout type="warn">
Writable-home expansion currently does not reliably exclude credential locations on Linux and Windows: a writable ancestor-directory rule becomes a recursive grant. Do not rely on writable home access to protect files such as `~/.ssh`. Read-only expansion and writable expansion have different enforcement behavior.
</Callout>

## Package exceptions

To run one dependency without the jail, set its approval to `"no-jail"` in the root project's `package.json`:

```json title="package.json"
{
  "allowScripts": {
    "native-addon": "no-jail"
  }
}
```

The package's scripts run with ordinary user access. Nub prints a notice; other dependencies retain their permissions.

For a local dependency, use its full specifier:

```json title="package.json"
{
  "allowScripts": {
    "native-addon@file:./native-addon": "no-jail"
  }
}
```

After changing an installed package's permissions, rerun its build scripts:

```sh
nub rebuild
```

## `install.buildJail`

The project-wide switch belongs in `nub.jsonc`. It defaults to `true`.

```json title="nub.jsonc"
{
  "install": {
    "buildJail": false
  }
}
```

Setting it to `false` removes the jail from every dependency build in the project. It does not approve scripts that were otherwise blocked.

User configuration supplies a default for all projects. Project configuration takes precedence.

```sh
nub config set install.buildJail false --global
nub config delete install.buildJail --global
```
